# Cliparts 6×6 の低解像度への取り残し

元画像は `5016 × 5016`。全体の初期変換は `1414 × 1414` で行い、個別のアイコンを元解像度で再変換して差し替える。

既存 SVG では 36 枠中 29 枠にしか差し替えがなく、3 行 1 列の人物を含む 7 枠は初期変換のままだった。同じ設定での再実行では、36 枠すべてが候補となり、すべての高精細版で品質と境界接続の条件を満たした。しかし追加 SVG の 32 MiB 上限により、最後の 7 枠を採用できなかった。初期解像度が選ばれた原因は人物の検出失敗や再変換の失敗ではない。

人物の対象範囲は元画像の `(160, 1686)` から `558 × 760`。初期処理では約 `157 × 214` に相当する。高精細版では評価値が `10.36 → 4.49`、平均 DeltaE が `5.00 → 2.22` に改善したが、約 1.67 MB の追加データが全体の容量制限で見送られていた。

既定の一律の追加容量上限を撤廃する（設定値 `0` は無制限）。各領域の品質改善と容量効率による採否判定は維持する。明示された `--adaptive-svg-budget-mib` の上限は引き続き厳守する。容量不足による見送りを `rejected_for_budget` として分離して報告し、通常の CLI 出力でも初期解像度のまま残った件数と原因を表示する。この件数は既存の `rejected_for_complexity` の内数である。

高精細版は容量判定より前に生成されるため、容量上限だけを低くしてもその生成時間は短くならない。変更の主なトレードオフは保存する SVG の容量である。

再生成結果は 36 / 36 枠を元解像度で採用し、容量不足の見送りは 0。SVG は 41,828,010 → 55,851,533 bytes。検証時の 64 MiB 制限にも達していないため、既定の無制限設定と採用結果は同じになる。比較画像: `sample/comparison/cliparts-6x6-detail.png`。
