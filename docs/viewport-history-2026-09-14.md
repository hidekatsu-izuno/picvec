# viewport2 の履歴比較と、旧版の出力を維持する高速化
> 履歴調査時点の記録。以下の415d64fへの復元は、その後の「最新Git版SVGと一致させる」という要件により取りやめた。現在の実装・検証は[最新版SVGを基準とする性能修正](latest-svg-performance-2026-09-14.md)を参照。

同じ `sample/input/viewport2.jpg`、release/diagnostics ビルド、`--threads 4 --verbose`、CLI既定値で履歴を遡った。各プロセスに300秒の上限を設け、測定中に別の変換・ビルド・テストを重ねていない。ソースは `/tmp/picvec-viewport-history/<revision>` に Git archive で展開した。作業開始時のソース・Cargo設定・テスト・スクリプトは同ディレクトリの `before-work.tar`、Git差分は `before-work.diff` に退避している。

## 増加した処理

### 1. 小さなOKLab配列にもRayonを使っていた

`c29c9b5` → `2ca36fe` で、viewport2の塗り統合（paint-aware-merge）が21.230秒から136.151秒に増加した。最終領域数は68,951から73,463で、領域数の増加だけで約6.4倍の時間差を説明できない。色空間や判定条件も変わっているため、この比較だけで原因を一つに断定しない。

コードでは、OKLabの `oklab_values` が要素数に関係なく `par_iter` を使う。統合判定では平均色2個、片側の標本、両側を合わせた最大384個などの色変換を大量に繰り返す。色変換が軽くなった一方、小さなジョブを投入・同期するコストが残っていた。

`415d64f`に出力を維持する高速化を加えた最初の試作（256色以下を逐次実行）では、このステージが141.759秒から72.317秒へ短縮した。全体も258.692秒から173.767秒へ短縮し、SVGのバイト一致を確認した。carは46.049秒から34.364秒、こちらもバイト一致。

384色の統合判定を並列側に残さないよう、次の試作では逐次実行範囲を1,024色以下に広げた。全画像の大きな配列は引き続き並列実行する。ここで変わるのは実行の分け方であり、RGB→OKLabの式や判定順序ではない。

### 2. 機能追加と高速化が同じ「Improve code」の履歴に含まれる

`db159b8` → `c29c9b5` では、輪郭推定、レイヤー簡略化、outline検証、構造線の色パッチなどが追加された。`2ca36fe` → `415d64f` でも、回転した放射グラデーションや残差モデル、形状の修正などが加わっている。純粋な高速化前後の比較として扱うことはできない。

その後の `725a082` には、塗り所有・透明度・微小領域の処理、描画順序の検証、隠れた穴の簡略化、不可視要素の最終検証などがまとめて追加された。前回の現行版測定では、viewport2の穴の検証に75.988秒、最終SVG処理に48.013秒かかった。これらは古い変換にはなかったコストであり、キャッシュを多少改善するだけでは旧版と同じ所要時間にはならない。

### 3. 安全な局所候補がない場合の処理が変わった

`725a082` の `adaptive::plan_candidates` に、局所候補が空で画像が大きい場合に全画像を候補へ追加する分岐が入った。viewport2は、1600×1067の基底変換の後、4272×2848の原寸で全体をもう一度変換する。この段階は旧版では実行していない。

したがって、単に `725a082` 以降の高速化を取り消すだけでは旧水準に戻らない。全体原寸変換は計算対象そのものの変更である。ユーザーが求めた旧viewport2の水準と、後発の原寸高精細化済み出力を同じ条件として扱わない。

## 厳密高速化の試作

`415d64f`を基準に、以下のみを移植した。`725a082` の品質閾値変更・追加の残差棄却条件などは含めない。

- 小さなOKLab配列を逐次実行。
- 局所最大値・円盤モルフォロジーのスライディング処理と、加算順序を保ったGaussian畳み込み。
- 中央値の順位選択。
- 残差候補の観測列共有、同じ座標パラメータの再利用、元の誤差判定に基づく早期棄却。
- ベジェ曲線の同じ距離評価における探索・計算の再利用。

[256色版のパッチ](viewport-history-2026-09-14/fast415.patch)は`415d64f`に対する差分。最終案は別パッチ・別測定として保存する。

## ビルドキャッシュへの対処

同じtargetディレクトリに古いmtimeのGit archiveを展開すると、別コミットのビルドが `Finished ... 0.03s` で終わり、前の実行ファイルが残るケースを確認した。最初のc29c9b5測定はバイナリが2ca36feと同一だったため停止・除外し、再ビルドして測定し直した。

以後は展開先src配下のファイルをtouchしてからビルドし、コンパイル実行とバイナリハッシュを確認する。共有targetを使う場合に、Cargoの終了成功だけで過去版を再現できたと判断しない。415d64f・2ca36feの出力は当時の保存資料のSVGハッシュとも一致した。

## 1,024色版の結果と復元方針

| 入力 | 415d64f | 256色まで逐次 | 1,024色まで逐次 | 415d64fとのSVG一致 |
|---|---:|---:|---:|---|
| viewport2 | 258.692秒 | 173.767秒 | **97.364秒** | 完全一致 |
| car | 46.049秒 | 34.364秒 | **22.380秒** | 完全一致 |

[最終案のパッチ](viewport-history-2026-09-14/fast415-1024.patch)、[測定JSON](viewport-history-2026-09-14/fast415-1024.json)。256色版と1,024色版の実行コードの違いは、小さな色配列を逐次実行する境界だけ（ほかにその境界のテスト入力を追加）。全体画像は縮小せず、415d64fと同じ1600×1067の処理・追加候補なしという既定条件を使っている。

この比較は現行の原寸高精細化済みSVGとの一致を主張していない。415d64fのviewport2は59,713,913 bytes、SHA-256 `def9930de87dda850a808ddb8e92397155533c334d026f58138a33e6a2582d3b`。carは2,568,073 bytes、SHA-256 `cde6266c0fd9debeb6aba6c194c8567ac033dffd19d127f3b3e2ed5cc5bc8144`。

ユーザーの巻き戻し指示に従い、作業ツリーの変換ソースとCargo設定を、この検証済みの415d64f＋1,024色版へ復元した。AGENTS.md・既存の調査文書・関連しないスクリプトは保持した。元のcar/viewport2 SVGも `/tmp/picvec-viewport-history/previous-svgs` に退避した。

これは、後発の機能を全部維持した最新版の高速化ではない。725a082以降の透明度・所有領域・隠れた幾何の除去・描画順序検証・全画面原寸再変換は復元先には含まれない。今回生成・比較するcar/viewport2は不透明入力で、出力にmaskがないことを確認する。旧版の透過入力経路は今回の適用・品質検証対象にしていない。退避した新しい透過処理を戻すときは、AGENTS.mdの塗り自身のalpha・mask禁止条件に沿って別途検証する必要がある。

推奨する進め方は、まずこの完了する基準にcarとviewport2の通し計測を固定し、その後の変更を機能ごとに戻すこと。全画面原寸再変換は既存変換とは別の計算量・出力なので、通常実行への無条件の復帰は避ける。透明度や必要な所有領域処理を先に独立して戻し、穴・可視性の検証は影響範囲を限定する正確な描画再利用と一緒に評価する。画像名による処理分岐や、誤差閾値・解像度の一律緩和は使わない。

## 作業ツリーからの最終再確認

通常の `target/release/picvec` を作業ツリーから再ビルドして逐次実行した結果は、viewport2 **97.929秒**、car **21.942秒**。試作時の97.364秒・22.380秒と合わせ、両画像とも2回ずつ正常完了し、毎回415d64fのSVGとバイト単位で一致した。

[最終測定](viewport-history-2026-09-14/restored.json)と `sample/output/viewport-car-timings.json` に記録し、`sample/output/viewport2.svg` と `sample/output/car.svg` を更新した。XMLとして解析し、mask要素・mask属性・グループopacityがないことも確認した。

- `cargo test --offline --release --features diagnostics --lib geometry:: -- --test-threads=4`: 73件成功。
- 同じ条件の `gradient::`: 56件成功、`ridge::`: 5件成功、`extrema::`: 1件成功、`edge::history_speed_checks`: 1件成功。合計136件、失敗0。
- `cargo check --offline --no-default-features --all-targets`: 成功。
- `git diff --check`: 成功。

対象は今回の厳密高速化を含む計算モジュールと、不透明なcar/viewport2の全変換。旧版の透過SVG生成や後発機能すべての適合性を確認した結果ではない。

再実行は、`cargo build --offline --release --features diagnostics` の後、`target/release/picvec sample/input/viewport2.jpg /tmp/viewport2-check.svg --threads 4 --verbose`、続いてcarを同じ条件で実行する。別のビルドや変換を重ねない。現在のソースからの通常ビルドと、今回測定したバイナリが同一であることを確認済み。
