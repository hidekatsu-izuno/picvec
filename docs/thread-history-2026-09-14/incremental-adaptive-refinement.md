# 粗い SVG を再利用する局所高精細化

比較元: `3fa41d2726efb77974a990666f5cd1ab28b85c5f`。

## 計測結果

AMD Ryzen AI 9 465、Rust 1.95.0、releaseビルド、4スレッドで、変更前後を交互に2回ずつ実行した中央値。

| 入力 | 変更前 | 変更後 | 局所処理の採用 |
|---|---:|---:|---:|
| 合成パネル、2048×2048、最大寸法256 | 48.910秒 | 1.118秒 | 1件 |
| `cliparts.png`、最大寸法512 | 48.675秒 | 48.368秒 | 0件 |
| `cube-alpha.png` | 0.817秒 | 0.804秒 | 0件 |

合成画像では約43.8倍。全4,194,304画素のうち局所変換は64,516画素となり、98.46%の範囲で粗い解を再利用した。既存2サンプルではSVGが変更前後で一致し、診断値も新しいゼロ値のカウンターを除いて一致した。既存サンプルの時間差は小さく、速度改善の証拠として扱わない。

合成画像の169個の印は両版とも原寸・4倍で残り、アルファの誤差は0だった。全画素の平均100倍OKLab色差は、原寸が **0.00472 → 0.04432**、4倍が **0.00507 → 0.04470**。再利用した背景の微小な色差が残る。SVGは12,340 → 12,548バイトとなり、完全一致ではない。

最終版の合成画像は1・4スレッドでもSVGが一致し、診断値は実行スレッド数を除いて一致した。実行ファイル・SVGのハッシュ、全12回の時間・診断値、独立したRGBA・色差測定は [測定データ](incremental-adaptive-refinement.json) に保存した。生のSVG・ログは `/tmp/picvec-incremental/validated/`、RGBA描画と色差測定は `/tmp/picvec-incremental/final/` にある。後者で検査したSVGと最終版のSVGがバイト単位で一致することを確認済み。

## 実装

高精細化の候補全域を変換し直す前に、粗い SVG を原画像の解像度で描画し、原画像との差が集中する範囲を探す。局所変換を採用できれば、その外側の曲線と塗りは粗い SVG を再利用する。領域分割・塗り推定・曲線近似を実行する画素数そのものを減らす方式であり、同一出力を保証する前回の探索高速化とは異なる。

適用条件は以下のとおり。

- 不透明画像で、候補の面積が 256 × 256 画素以上。
- 全画素を調べ、いずれかの RGB チャンネルの差が 4/255 を超える画素を囲む。離れた細線や小さな印もサンプリングで飛ばさない。
- 差分の周囲に16画素の背景を確保でき、切り出しの余白も含めて、その背景が1/255以内で均一。既存の線やグラデーションを横切る範囲は使わない。
- 変換用の余白も含め、処理範囲が元の候補面積の1/4以下。
- 置換範囲に完全に含まれる粗い描画オブジェクトがないこと。不要な図形を隠して残さない。
- 従来の品質・欠落エッジ・SVGバイト当たりの改善量の検査に合格し、接合部が原寸と4倍描画で一致すること。

局所変換が品質・複雑度・接合の検査に不合格なら元の候補全域で再試行する。最終的なSVGのバイト予算は従来と同様に候補の評価後に適用する。透明・色抜き画像は従来経路を使う。局所変換の採用時は幾何クリップで置換範囲を粗い SVG から除き、透明度をマスクで表現しない。クリップの外側では従来の形状と塗りを保持する。不透明な接合部には粗い解の1画素分の重なりを残す。補完関係にあるクリップでも、アンチエイリアスの合成により透明な継ぎ目が生じ得るためである。

診断情報に `local_refinement_attempts`、`local_refinement_accepted`、`reused_source_pixels` を追加した。後二者は最終バイト予算に収まった採用分だけを数える。`reused_source_pixels` は元の候補の拡張範囲から採用した局所変換範囲を引いた原画像上の面積であり、実行命令数や速度倍率ではない。

この経路は誤差が局所に集中する場合を対象とする。全体に誤差が分布する画像、連続するグラデーション、透過画像の高精細化全般を高速化するものではない。全画素の差分検査には追加コストがあり、条件を満たさない実画像でも計測する必要がある。

## 検証

- `cargo test --release --lib --locked --features diagnostics`: 436件成功、失敗0、既存のスキップ7件。
- 追加テストは、離れた微小な印を含む差分範囲、既存の線・グラデーションを切らない条件、実際の局所変換と全域へのフォールバック、細い線による接合不一致、端数座標での合成を検証する。
- 局所変換で生成したSVGを原寸と4倍でRGBA描画し、細かな印と再利用した外周を確認する。端数座標の合成では粗い解の倍率でも継ぎ目を検査する。
- 既存の透過・細線・報告済み微小オブジェクトのSVG検査も全体テストに含む。
- `cargo check --locked --no-default-features`、変更したRustファイルの`rustfmt --check`、Pythonの構文チェック、`git diff --check`も成功。通常構成では既存の `paint_order::Proposal` の未使用フィールド警告が1件残る。

## 再現

```sh
python3 scripts/benchmark_adaptive.py \
  --baseline /tmp/picvec-incremental/baseline \
  --candidate /tmp/picvec-incremental/candidate-final \
  --output-dir /tmp/picvec-incremental/reproduce \
  --cases sparse-large adaptive-small alpha --repeats 2 --threads 4
```

このスクリプトは候補名、実行ファイル・SVGのハッシュ、全診断値、段階別時間を保存する。`sparse-large` は2048×2048の不透明なパネルに169個の2×2画素の印を置いた画像で、外部ライブラリなしで生成する。比較の実行順は交互とし、並行実行しない。出力が変わり得るため、`benchmark_exact.py` の完全一致判定は使わない。

## 画質の比較方法

合成画像のSVGを `rsvg-convert` で2048×2048と8192×8192に描画する。原画像を4倍にする際は最近傍補間を使い、RGBAの二乗平均平方根誤差、最大誤差、全画素の平均100倍OKLab色差を計算する。加えて、169個すべての印の中央画素を調べる。大きな背景の平均値だけでは微小な印の欠落を判断できないためである。

この色差は独立レンダラーによる全画素の測定値であり、パイプラインが候補選定に使うサンプリングされた推定値とは別の指標である。局所再利用では粗い解の小さな色誤差も引き継ぐため、従来版とのSVGの完全一致や、全域を再処理した場合と同じ誤差は保証しない。
