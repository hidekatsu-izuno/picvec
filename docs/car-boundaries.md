# car の OKLab 再調整と導入前比較

> 過去の再調整記録です。この表と拡大比較の OKLab は SHA-256 `9b64c33e…` の版です。その後の窓枠修正と現在の出力は [car の窓枠調査](car-windows.md) を参照してください。以下の「現在の SVG」「車全体の比較」リンクは更新後のファイルを指します。

ボンネットに多数の三角形が出た版を置き換え、追加の細分割・輪郭補正を取り除いた。導入前の領域分割と輪郭生成を基本に戻し、OKLab の判定値を調整した。色空間の変更によって大きな三角形や輪郭の粗さが発生する必然性はない。

## 比較の基準

CIELAB 基準は `57c3a4ac7347504a6e4771fb1affd9071dbdf27e`。別ディレクトリでそのソースをビルドし、同じ入力を再生成した。保存済みの導入前 SVG と SHA-256 が完全一致した（`c7ff5f3993b3fa5f724ed5b494cacc3cdad5f8f3eb4a57d23d1f5a019ea64e03`）。前回の OKLab 修正版を基準にはしていない。

CIELAB/CIEDE2000 と100倍スケールの OKLab 距離は、単一の倍率では一致しない。特に黒付近では、8-bit RGB の 0→1 が約6.72 OKLab単位になる。従来の小さい平滑化閾値のままでは、その1段階のノイズまで境界として残る。したがって判定値の校正は必要だが、色空間を理由に別の細分割・輪郭アルゴリズムへ置き換える必要はなかった。

## 変更内容

1. 後から追加した微細な色面分割、補助的な輪郭グループ、画素未満の輪郭位置補正、小片の追加整理を撤去した。導入前からある適応的な高解像度補正は維持した。
2. 黒付近の8-bitノイズに対する平滑化許容量、明部の平滑化、暗線の明度基準、色チャンネルの正規化、保護する細部のパレット閾値を校正した。設定は [OKLab の説明](oklab.md) に記録した。
3. 再現できる局所的な計算不具合だけを修正した。不等間隔のグラデーション停止点では傾きを考慮して正則化し、狭い観測範囲では存在しないサンプルを補って傾きを変えない。小面には実際の局所色を使い、大量のサンプルの平均は float64 で蓄積する。
4. SVG の塗りの重なりは0.3画素にした。バンパー `(286,752)` は、入力と塗りの計算結果は正しかったが、共有境界のアンチエイリアスから背景色が透けていた。0.2→0.3で最大RGB誤差は18→10になった。0.5では窓と細い境界の既存テストが失敗したため採用していない。新しい輪郭補正は追加していない。

## 結果

| 指標（小さいほど良い） | 導入前 CIELAB | 再調整 OKLab |
| --- | ---: | ---: |
| 全体の平均 OKLab 色差 | 0.6961 | 0.6832 |
| 前輪上のテスト領域の平均 RGB 誤差 | 3.7369 | 3.5691 |
| ボンネットの平均 RGB 誤差 | 3.8592 | 3.4227 |
| バンパーの平均 RGB 誤差 | 3.2862 | 3.0195 |
| フェンダー境界の凹凸（画素） | 0.14885 | 0.12304 |
| 窓枠境界の凹凸（画素） | 0.15911 | 0.09720 |
| ホイール境界の凹凸（画素） | 0.28980 | 0.27162 |
| SVG bytes | 1,982,104 | 1,866,604 |
| 領域数 | 1,887 | 2,015 |

凹凸は元画像の境界に沿う位置列の2階差分の絶対値の平均。これだけで画質を判定せず、拡大図も確認した。問題のあった版は3,107,771 bytes・3,896領域で、平均色差はむしろ0.6574と小さかった。平均色差だけを最適化しても、三角形や不自然な輪郭を検出できない。

ボンネットの多数の三角形、窓枠の突起、ホイールの細かい凹凸は問題のあった版から改善した。一方、元画像の滑らかな濃淡を完全に再現してはいない。CIELAB版にもある色面の段差と細い継ぎ目は残る。窓枠の平均位置誤差は0.280→0.530画素で、滑らかさとは別に位置の差も残っている。全箇所でCIELAB以上になったという結論ではない。

以前の「逆転画素対2%未満」は、細かい色面を大量に作る版を通してしまった。導入前のCIELABも前輪上で約10.4%になるため、この値だけを回復の基準にはしていない。今回の前輪上は約6.7%、バンパーは約6.4%。定義と個数を結果JSONに残した。

## 回帰検証

黒の1階調ノイズを平滑化しても実際の黒線を消さないこと、停止点の間隔に依存して直線的な濃淡が曲がらないこと、狭い観測区間の傾き、局所色、大面積の平均精度をテストした。実画像テストでは従来の平均RGB誤差3.65未満を維持し、報告された3点の色、フェンダー境界の凹凸0.16画素未満・位置誤差0.4画素未満も確認する。なお再現した導入前HEAD自体の平均誤差は3.7369であり、この3.65の条件は満たしていなかった。

正式な release 設定で通常テスト289件成功（既存の ignored は4件）。車の実画像テストと `cliparts-6x6` の図形単位の補正候補テストも明示実行して成功した。clippy（全ターゲット・警告をエラー化）、通常機能での cargo check、Python 12テスト、整形・差分チェックも成功。

```sh
cargo test --release --locked --offline --features diagnostics
cargo test --release --locked --offline --features diagnostics \
  car_front_fender_highlight_keeps_local_shading -- --ignored --nocapture
cargo test --release --locked --offline --features diagnostics \
  clipart_sheet_refines_whole_figures_with_and_without_keying -- --ignored --nocapture
cargo clippy --release --locked --offline --all-targets --features diagnostics -- -D warnings
cargo check --locked --offline
cargo fmt --check
PYTHONPATH=scripts:. python -m unittest discover -s tests -v
```

追加実行した `cliparts_highlights_preserve_colour_and_authored_transparency` は成功した。一方、`cliparts_penguin_inner_foot_outlines_remain_continuous` は `(1003,689)` の1行で未達。保存済みCIELAB版も同じ測定では5行が未達だった（y=710,711,712,716,717）が、今回の1行は場所が異なる。これは未解決の細線の描画差として残し、テストを緩めて成功扱いにはしていない。

全サンプル再生成の最後に、ロゴの無彩色領域で百分位点の浮動小数点補間が上下限を1 ULP程度逆転させ、`clamp` が停止する不具合も再現した。グラデーション停止点の制約を適用する前に上下限を順序づけた。正常な上下限には数値的な変更を加えない。平坦な色と複数のサンプル数による回帰テストを追加した。


現在の `sample/input` の9ファイルからSVGを再生成し、一覧の比較画像も更新した。[全出力のハッシュ・生成条件・検証記録](oklab-calibration-samples.json)を参照。`cliparts-6x6` は36図形すべての高解像度補正を採用した。[ディスク・サーバラック・ギアの再確認](cliparts-6x6-refinement.md)も記録した。
