# 滑らかな陰影の領域統合と境界

通常変換では、色面の境界を保持しながら、グラデーションで表現できる領域の
機械的な細分割を避ける。以下に現在の判定と検証結果をまとめる。

## 原因と変更

- **元画像の内部を見ずに統合していた。** 量子化の境界と元画像の色の段差は一致しない。
  モニターの切り出しの y=150 では、既存の領域境界は x=403、元画像の主な色の変化は
  x=423 付近にある。領域境界上の隣接 1 画素だけを調べても検出できない。
  統合候補の内部を最大 4,096 点調べ、4・8 画素の距離で中央の色差と両側の色勾配を
  比較する。色変化の集中が複数点にある候補は統合せず、既存の所有者を残す。
- **ぼかされた境界を連続した陰影として扱っていた。** 境界上でも同じく複数画素幅の
  色変化を調べ、段差の証拠がある統合を止める。一定勾配では中央と外側の変化量が
  近いため、局所的な段差と区別できる。追加判定は統合プリチェックと、その出力を
  含む境界の色合わせに限定する。
- **領域を評価する前にパッチへ分割していた。** 統合されなかった既存の大きな面も、
  分割前に一つのグラデーションとして評価する。内部の標本で平均 ΔE00 ≤ 1.8、
  p90 ≤ 4.0 を満たす面には推定した Paint を渡し、機械的な細分割を省く。
  滑らかな境界では隣接する Paint と色を合わせ、本来の色面の境界は保持する。

画像名・画面座標による特別扱いは変換処理に入れていない。
段差を消す統合候補を取り消す。
円筒側面のような連続した陰影の統合は継続する。

## ガラス面の修正時の測定

直前のラップトップ修正版を before とし、4 スレッド・元解像度・背景除去ありで比較。
数値は [測定記録](coherent-glass-fields-results.json) の固定 ROI。
平均 ΔE00 は小さいほどよい。領域数には、細い遷移部分や小さな断片も含む。

| 部分 | 平均 ΔE00：前 → 後 | 領域数：前 → 後 |
| --- | ---: | ---: |
| モニター画面 | 0.596 → 0.710 | 4 → 4 |
| 車のガラス面 | 1.073 → 0.577 | 7 → 5 |
| ラップトップ画面 | 0.445 → 0.758 | 26 → 16 |
| 円筒の上段側面 | 1.300 → 1.277 | 3 → 4 |

元の同じ領域内に後から追加された境界を、ROI 内の上下左右の隣接画素で数えた。
車は 136 → 0 辺、ラップトップは 1,198 → 0 辺、円筒は 29 → 6 辺。
モニターは 17 → 17 辺で、小さな断片の分割は残っている。
この数値は量子化が元から作っていた境界や、本来の色面の境界を含まない。

車の誤統合は解消したが、すべての画質指標が改善したわけではない。
モニターとラップトップの一部の色誤差は増えた。元画像にない量子化の輪郭も一部残る。
**全ガラス面を厳密に 3 領域にした実装ではない。**
機械的なパッチ分割を回避できる面を増やした段階であり、量子化でずれた輪郭の復元は
別途必要になる。ROI の領域数だけを最小化すると、本来残すべき色面まで消してしまう。

時間は各 1 回の診断付き実行で、安定した高速化率の測定には使わない。

写真は別途、4 スレッドで交互に 3 回比較した。中央値は 13.90 → 14.75 秒
（約 6.1% 増）、平均 ΔE00 は 3.377 → 3.317。従来の 2 つの統合候補を拒否したため、
個別のモデル探索が増えた。写真での時間増加は残る。[測定記録](coherent-glass-fields-regression.json) を参照。

[通常の全シート SVG](../sample/output/cliparts-6x6.svg) も再生成した。

## 通常変換

```sh
mise exec -- cargo build --release --locked --offline --features diagnostics
target/release/picvec sample/input/cliparts-6x6.png /tmp/cliparts-6x6.svg \
  --threads 4 --remove-chroma-key-background --verbose
```

ぼかされた段差と一定勾配の区別、領域内部の段差の誤統合防止、単独面の分割回避を
回帰テストに追加。全機能・全ターゲットで 221 件成功、3 ignored。
Clippy（警告をエラー扱い）、書式チェックも成功。

## 車のドアの陰影

`car.png` のドアでは、先にフィットした面を色合わせから一律に除外していたため、
滑らかな陰影に帯状の段差が残っていた。色合わせを有効にするだけでは、その後の
ペア単位の調整が片側だけを変更し、そろえた色を再び不連続にする場合があった。

元画像が滑らかな境界では先行フィット済みの面も色合わせに参加させる。
一緒にフィットする際は画素数に比例して標本を配分し、細い帯が大きな面と同じ重みで
陰影を変えないようにする。採否の誤差比較には従来の面ごとの標本を使う。
そろえた先行フィット済みの面のグループは、後段の部分的なペア調整から保護する。
色合わせの反復中に構成面が変わっていない組み合わせは再評価しない。
この再評価の省略前後で、車の SVG がバイト単位で一致することも確認した。
ぼかされた本来の色面の境界は色合わせの対象にしない。

元解像度 1254×1254、4 スレッドで確認した。ドア内の矩形
(x=560, y=560, 幅350, 高さ200) で、平均絶対RGB誤差（8ビット値）は
3.533 → 2.881。中央の矩形 (630, 640, 240, 60) では 2.338 → 2.240。
中央で問題になった2面のグラデーションは同一になり、両者間の色の段差はなくなった。
ドア上側のハイライトなどに残る細かな量子化の帯をすべて除去する変更ではない。

回帰テストでは、先行フィット済みの面の滑らかな境界を修正し、ぼかされた素材境界は
変えないことを同じ変換経路で検証する。


## フェンダーと局所ハイライト

広い面の平均誤差だけで先行フィットを確定すると、局所的な陰影の誤差が隠れた。
先行フィットは分割省略の判定に使い、色の最終推定の完了とはみなさない。
通過した面は保持し、必要なら最大8枚の柔らかな重ね塗りで局所的な陰影を補正する。
後段の色合わせでも32画素四方ごとのRGB誤差の
増加を確認する。局所平均を0.5階調より悪化させる調整は採用しない。

量子化された細い色帯の内側だけでは、帯を横切る勾配を推定しにくい。
素材境界で止めた8画素以内の標本の拡張、元画像の微分からの方向推定、
面の外側にも中心を置ける楕円グラデーションを評価に加えた。
輪郭用に除外されていても、元画像と下塗りが一致し周囲が滑らかな画素は
Paintの標本へ戻す。実際に除去した線の画素は戻さない。

単一のグラデーションで説明できない局所的な明部には、最大3枚の柔らかな
放射状の重ね塗りを評価する。単独の外れ値ではなく、同じ方向の色誤差が
集まる場所に配置し、元のフィットより誤差が小さい場合に採用する。
重ね塗りした面は、単一グラデーション用の境界調整から除外する。
一次判定を使う高密度画像でも、局所的に滑らかなハイライトは評価候補に残す。
今回の通常のcar/clipartsでは、この一次判定は作動していなかった。

フラスコとペンギンには透明度の変化も含まれる。従来の4段階の透明度マスクでは
RGBを正しくフィットしても段差が残るため、連続した透明度はグラデーションを
使う輝度マスクで表す。透明度側の詳細は
[背景・透明度の処理](chroma-key-background-removal.md)を参照。

画像名や座標による特別扱いはない。検証用の切り出しと途中のSVGは `/tmp` に置き、
通常のcar/clipartsのSVGとREADME用比較画像だけを更新する。

## サボテン下の点線の輪郭

`cliparts.png` の黄色い楕円は、元画像では細い点線で囲まれている。
線グラフの接続・簡略化後に一定幅の線を重ねたため、点線が部分的な実線になり、
上端では透明画素の黒いRGB値まで根拠にして約4.3画素幅の線が描かれていた。

接続後の線に、元画像の法線方向の濃度分布を使う再測定を追加した。
細い線の濃さが繰り返し減る場合に限り、局所的な幅と中心を保持した短い区間へ戻す。
区間の端を丸く延長して隙間を埋めない。透明度がある場合は画素ごとに合成してから
補間する。RGBと透明度を別々に補間すると、透明な黒から偽の暗部が発生するためである。

欠落した微小な点を補う場合も、元画像で点線と確認した線の端同士に限定する。
互いに最も近く、方向と色が一致し、中間にも反復する元の線がある場合だけ補う。
元画像に点がない隙間は接続しない。画像名、座標、楕円であることによる特別扱いはない。

元解像度・白背景・同じresvgでの平均絶対RGB誤差（0〜255）は以下のとおり。
矩形は `(x, y, 幅, 高さ)`。

| 箇所 | 評価矩形 | 修正前 | 修正後 |
|---|---|---:|---:|
| 円の上端 | (500, 309, 30, 11) | 35.537 | 5.945 |
| 円を含む範囲 | (468, 310, 78, 58) | 6.518 | 3.399 |
| 下側の欠落部 | (514, 355, 21, 11) | 9.479 | 5.163 |

フラスコ上部とペンギン頭部の既存評価範囲は、修正前後で描画誤差が同じだった。
通常変換は4スレッドで24.858秒。SVGは2,468,911→2,564,625バイト。
点線の局所的な幅を保持するため要素数は増える。単発測定で高速化を示すものではない。
元画像の低解像度に由来する輪郭の細かな揺れは残る。

通常テスト231件と元解像度の実画像テスト3件が成功。
点線の隙間、透明な黒の除外、実線の保持、元の点がない区間をつながないことを検証した。
Clippy（警告をエラー扱い）、デフォルト機能のビルドチェック、書式チェックも成功。
通常のcliparts.svgと既存の比較画像を更新し、診断・切り出し画像は `/tmp` のみに置いた。
