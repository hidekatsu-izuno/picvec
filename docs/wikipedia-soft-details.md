# Wikipedia ロゴのぼけた陰影

元画像の右上、斜めの外周付近にある灰色の突起はぼけた陰影である。塗りを領域に分けて硬い輪郭で描くため、SVG の拡大表示では灰色の破片や角張った形に見えた。構造線を外した描画にも残るため、線の削除だけでは解消しない。

`soft_edges` は完成した描画と元画像を小さな範囲ごとに比較し、局所的な Gaussian blur が改善する場合だけ採用する。現在は主に無彩色の画像を対象とし、黒い文字や色のある部分を含む範囲は除外する。鮮明な図形は、ぼかすと誤差が増えるため採用されない。

- 24 px 四方で候補を調べ、0.6 / 1.0 / 1.5 / 2.0 px のぼかしを比較する。予測誤差が 10% 以上減る候補を最大 512 個まで選ぶ。
- 半透明の境界では、背景の白をぼかすのではなく、色を透明度で重み付けして予測する。比較用の背景は白とし、内部診断用の色付き背景を使わない。
- SVG を実際に再描画し、範囲内の誤差が 5% 以上減る補正だけを残す。元の透明マスクを再適用するため、切り抜きの外へぼかしが広がらない。
- 同じぼかし量は一つの `use` で元のベクター描画を共有する。描画インスタンスは最大 4 個で、範囲ごとの複製によるパーサー上限・描画負荷の増加を避ける。ビットマップは埋め込まない。
- 隣接する同じ強さの補正範囲を結合してから、外周 4 px で効果を弱める。内部のタイル境界に硬い線を残さない。

フィクスチャ `wiki-soft-source.png` と `wiki-soft-before.png` は、元画像と修正前 SVG のネイティブ描画の `(792, 48)` から `96 × 96` の切り出し。透明境界にある突起を検出できることを検証する。合成例の SVG 再描画テストでは、ぼけた陰影への改善、鮮明な図形の維持、内部タイル境界の連続性を確認する。拡大再変換の埋め込みでは `href` も ID と同じ接頭辞に変更する。

再生成後、対象の突起周辺 `(816, 72)` から `48 × 24` のネイティブ画素を白背景で比較すると、修正前 SVG に対する二乗誤差は約 25% 減った。`sample/comparison/wikipedia_logo_1_0-detail.png` は左から元画像・修正前・修正後。形状の完全な復元ではなく、元画像で確認できるぼけへの局所的な近似である。
