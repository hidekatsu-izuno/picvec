# car の三角形状の色ムラの修正

> 過去の中間実験の記録。ここで説明する追加細分割は撤去した。現在の実装・出力・検証結果は [再調整の比較](car-boundaries.md) を参照。

この文書は三角形状の色ムラを修正した時点の記録。最新の輪郭修正と OKLab 導入前との比較は [輪郭の比較記録](car-boundaries.md) を参照。

前回の出力（SHA-256 先頭 `11ef3baa`）は、逆転率が下がっていても、尖った暗い小片や明るい境界を増やしていた。前回の「改善」という評価は不十分だった。今回は平均値だけで判定せず、推定色のラスタと SVG の描画結果を分けて調べ、実際に色が乱れた位置を拡大して照合した。

## 確認した不具合

### 分割した小片が親領域の色を引き継いでいた

空間的に分割した子領域でも、単色候補を親領域の量子化代表色から作っていた。その色は広いグラデーションの別の位置を代表しており、小片自身の色とは一致しない。さらに、小さな領域ほどグラデーションの採用に必要な改善量を大きくする条件があり、誤った単色がそのまま残っていた。

フェンダーの (335,655) では、元画像 `[253,93,86]` に対して `[243,73,67]` の暗い三角形状の小片ができていた。SVG の輪郭を作る前の推定色にも同じ誤りがあり、色空間の違いや閲覧ソフトだけでは説明できない不具合だった。

同じ Paint キーを共有する空間的な子領域については、それぞれの有効な元画像サンプルから単色候補を求めるようにした。これにより、小さすぎてグラデーションを採用しない場合にも、その場所の色で塗られる。

### 共有境界で背景が透けていた

別々の面のアンチエイリアス被覆率は単純には加算されない。例えば、それぞれ被覆率 50% の面を重ねても被覆率は 75% にしかならず、背景が残る。この透けが色面の内部に明るい線を作っていた。

元画像の色が滑らかにつながる内部境界だけに、共有曲線に沿った幅 1.5 画素の補填を追加した。周囲の隣接 RGB 差が各チャンネル 3/255 以下である区間を選び、元の曲線をその区間で切り出す。塗りの後、実際の輪郭や構造線の前に同じ Paint で描くため、実際の輪郭全体を太くする処理ではない。レイヤー付きグラデーションは下地と重ねた色を順に描画する。

OKLab、既存の分割幅、実際の材質境界に用いる重なり幅は維持している。入力画像の変更や画像の SVG 埋め込みは行っていない。

人工的な段差は、従来の前輪上 x=[320,530)、y=[565,645) の隣接画素対で、元画像の最大 RGB 差が3以下なのに、描画結果の最大 RGB 差が元画像より8を超えて増えたもの。

連続した元画像との近似誤差や一部の段差は残っている。すべてのグラデーションの逆転を解消したという評価ではない。今回の変更で SVG サイズは約9%増えた。詳細な条件、測定値、ハッシュは [JSON](car-front-fender-results.json) に記録した。

## 検証

- 1画素・三角形状の子領域が、親の量子化色ではなく自身の元画像の色を保持する回帰テスト。
- 斜めの共有境界で背景が透ける現象を再現し、補填後の被覆率を確認する描画テスト。
- 実際の材質境界と画像外周を補填対象にしないテスト。
- 車の実画像テストに、上記3か所の RGB 最大チャンネル誤差が10以下という条件を追加。前回の出力は3か所とも失敗する。既存の平均誤差・段差数・逆転率の条件も維持する。

正式な release ビルドで通常テスト299件が成功（既存の ignored は4件）。車の実画像テストも明示実行して成功した。clippy（`-D warnings`）、通常機能の `cargo check`、`cargo fmt --check` も成功。入力画像8件のハッシュは変更前と一致した。

```sh
cargo test --release --locked --offline --features diagnostics
cargo test --release --locked --offline --features diagnostics \
  car_front_fender_highlight_keeps_local_shading -- --ignored --nocapture
cargo clippy --release --locked --offline --features diagnostics -- -D warnings
cargo check --locked --offline
cargo fmt --check
```
