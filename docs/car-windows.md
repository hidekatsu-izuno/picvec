## なぜ CIELAB 版では目立たなかったのか

今回の劣化は、OKLab を使うと輪郭が必然的に粗くなる現象ではない。色差を使う判定の数値が変わって、同じ暗線の陰影を別の輪郭として扱うなど、後段に渡す形が変わったことが入口だった。そこに、画素単位の補修と線幅の推定にある問題が重なった。パラメータの校正を先に検証すべきだった。

具体的に、元画像の隣接点 `(842,336)` と `(842,337)` は RGB `(18,0,0)` と `(26,23,24)`。この2色の色差は CIEDE2000 では **6.153**、本実装の100倍 OKLab では **10.339** となる。幾何処理の連続性判定に同じ **6.9** を使うと、従来つながった暗い陰影が分離する。この判定を **10.5** に校正した。これは陰影が滑らかな輪郭を共有できるかの判定であり、塗りの色を一色に潰す変更ではない。隣の灰色部分までつながないこともテストした。

また、黒付近では8-bit中性RGBの0→1だけで約6.7 OKLab単位になる。暗線の色合わせに従来の数値を適用すると、量子化によるわずかな違いで滑らかな輪郭候補を棄却する場合があった。暗線の参照色の中央値が OKLab L<20 の場合だけ誤差許容量を3.1→4.0にし、有彩色の縁は3.1を維持した。全色を4.0にする試行は Wi-Fi の回帰テストに失敗したため採用していない。

したがって「CIELABとOKLabは同じ数値で判定できる」とは言えないが、「OKLabだから大きく劣化して当然」でもない。CIELAB版にも拡大すると小さな段差や切れ目はある。今回の比較から言えるのは、CIELAB版ではこの入力に対する分割・連結が異なり、問題の出方が小さかったことまでであり、すべての不具合がCIELABでは発生しないということではない。

## 修正した処理

1. **不要な画素補修。** 前景色の濃さを推定する係数を1に切り詰めてから残差を調べていたため、同じ色方向の濃い線まで別の色と誤認していた。判定前の上限クリップを外した。また、元画像の前景内部にある3×3の支持領域を要求し、輪郭のアンチエイリアス画素を矩形パッチで埋めないようにした。実際に内部にある別色の模様は維持する。
2. **内側の境界を外側と見なす輪郭復元。** ガラス側の境界を外縁として扱う場合、元画像の線幅・位置と復元する帯が一致しなかった。法線方向の元画像プロファイルを測り、十分な支持がある場合に一度だけ外縁に合わせ直す。平行曲線は既存のストローク展開器で生成し、両側を同じ基準曲線に対応付ける。
3. **復元した縁の両側を整合させる。** 黒線だけ描き直すと、元の塗りの黒い突起が外側に残る。位置を合わせ直した帯では内外各1.25画素の隣接色も元画像から復元し、変更した範囲全体を色差で評価する。内外に別々の下塗りを用意し、ガラス色の下塗りが外側に透ける細線も防いだ。元画像に対する位置誤差の許容量を一律に増やす修正ではない。
4. **下枠の短線の幅。** 領域マスクから得た幅が、実際の黒い芯ではなく灰色の陰影まで含んでいた。孤立した直線状の暗線について元画像の両側プロファイルを調べ、安定して支持される場合だけ中心と幅を測り直す。該当線は約4.886→1.800画素になった。特定座標の線を消す処理ではなく、太い帯や片側だけの段差には適用しない。
5. **曲線近似の潜在的な棄却。** パラメータを変えた調査用出力で、隣接する同点の角候補を両方残して1辺だけの区間を作り、閉曲線全体が棄却される問題も再現した。決定的な同点処理を追加し、順方向・逆方向の実輪郭で検証した。ただし、これは元の既定設定の窓枠を悪化させた主因とは区別する。曲線の分割数や採用コストを一律に緩める実験は残していない。

平行曲線の対応付けや両側の下塗りは、今回の修正を正しく成立させるための変更であり、CIELAB導入前から同じ形で存在していた不具合と混同しない。以前修正したグラデーションの停止点・局所平均の処理は維持した。

## 比較結果

色の誤差は白背景・元解像度1254×1254。上側の色評価範囲は `(700,325)–(975,425)`、下枠は `(735,495)–(831,521)`。段差の指標は4倍描画から元画像に対応する境界位置を取り、元画像1列ごとの位置列の2階差分の絶対値を測ったもの。単なる最大位置ずれではない。

| 指標（小さいほど良い） | CIELAB | 修正前 OKLab | 修正後 OKLab |
| --- | ---: | ---: | ---: |
| 上側領域の平均 RGB 誤差 | 4.0538 | 4.3998 | 4.0512 |
| 上側領域の平均 OKLab 色差 | 1.5791 | 1.6873 | 1.5655 |
| 黒い縁・ガラス側の最大2階差分（画素） | 0.7798 | 0.8145 | 0.2090 |
| 黒い縁・反対側の最大2階差分（画素） | 1.0349 | 0.2430 | 0.1539 |
| 黒い縁の交点を検出できない列数 | 5 | 0 | 0 |
| 外側の灰色境界の最大2階差分（明度50） | 0.3485 | 1.0705 | 0.4563 |
| 下枠領域の平均 RGB 誤差 | 7.7874 | 12.1392 | 7.6454 |
| SVG bytes | 1,982,104 | 1,866,604 | 1,877,109 |

黒い縁の連続性と急な突起は改善した。外側の灰色境界は修正前より改善したが、明度50・60の位置ではCIELABより小さな段差が多く残る。周囲の塗りやハイライトの色面境界も完全に滑らかになったという結果ではない。全箇所でCIELAB以上になったとは主張しない。

下枠の `(780,506)` の最大RGB誤差は31→4となり、その下の黒い芯 `(780,509)` は誤差3を維持した。前輪上の既存マスク内の平均RGB誤差は3.5691→3.5558。既知のバンパー・フェンダー点、ホイールアーチの凹凸・位置ずれも既存の回帰基準を通過した。修正後の全体平均OKLab色差は0.6777だが、全体平均だけを合否には使っていない。

## 検証と再生成

通常のRustライブラリテストは **297件成功、4件は既存の通常スキップ対象**。そのうち車、clipartsのハイライト・透明度、6×6の全図形の適応的精細化を明示実行して成功した。6×6は選択処理のテストであり、全SVGの再生成ではない。ペンギンの足の既存スキップテストは今回再実行していない。以前の失敗記録は過去の校正結果に残している。

```sh
CARGO_PROFILE_RELEASE_LTO=false CARGO_PROFILE_RELEASE_CODEGEN_UNITS=16 \
  cargo test --release --locked --offline --features diagnostics --lib
# 上記と同じビルド設定で、それぞれのテスト名を指定して実行:
# cargo test --release --locked --offline --features diagnostics <name> -- --ignored
# car_front_fender_highlight_keeps_local_shading
# cliparts_highlights_preserve_colour_and_authored_transparency
# clipart_sheet_refines_whole_figures_with_and_without_keying
cargo check --locked --offline
```

新しい回帰ケースには、暗線の色の連続性、不要な内部色パッチ、実窓輪郭の平行曲線・角処理、下枠の実線幅、上枠両側と灰色境界の急な段差、下枠2点の色を含めた。出力のSHA-256は `55ba19378953620d0de4caff014fbf6429ebd4c039b383d0ffdb9e1907517bf9`。今回更新した生成物は車のSVGと車の比較画像。他のサンプルの出力・以前の測定値は、今回のソースで再生成したものとして扱っていない。
