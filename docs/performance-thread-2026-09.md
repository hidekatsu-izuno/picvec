- このスレッドの高速化の比較起点: `725a082da21d067b0d10bcc7f722f7930ac0cd03`。
- 巻き戻し調査を開始した時点のHEAD: `3fa41d2726efb77974a990666f5cd1ab28b85c5f`。
- 方針: 精度を下げず、重複計算、処理順、探索アルゴリズムを見直す。
- CPU上限は変更しない。既定は利用可能な論理CPU数の半分、最低1・最大4スレッド。明示した `--threads` も従来どおり尊重する。

- 完了した比較ではSVGのSHA-256と診断値を照合した。通常、診断値から除外するのは経過時間と出力先のみ。スレッド数を変えた比較ではスレッド数の診断値も別扱いにした。

### 段階1: 初期の計算再利用

対象: `src/geometry.rs`、`src/pipeline.rs`、`src/gradient.rs`、`src/segment_micro.rs`、`scripts/benchmark_exact.py`。

- `PreparedGeometry` により、共有輪郭の推定と描画順依存の組み立てを分離。描画順を検証し直す場合も推定済み輪郭を再利用し、不要になった時点で解放する。
- 残差候補の検証では、元画像と元の塗りに関する色差を必要な画素だけ計算し、候補間で再利用する。
- 独立した塗り候補を既存プール内で並列評価し、従来の順番に戻してから採用候補を選ぶ。同点時や貪欲統合の順序を変えない。
- 微小領域の近傍画素収集を一度の窓走査にまとめる。領域ごとの画素順と局所色・アルファの証拠を維持する。
- 比較スクリプトに小写真・小さな高精細化ケースと任意のタイムアウトを追加した。

詳細: [初期の性能改善](performance-thread-2026-09/reports/performance-2026-09-13.md)。

## 6. 再開・再適用するとき

1. 初めに実行中の変換がないことを確認する。大画像のベンチマークとビルド・テストを重ねない。
2. どこを比較起点にするかを固定する。`415d64f` 以前への全面巻き戻しは画質・透明度処理の変更も取り消し、古いSVGマスク処理も含むため、`725a082` 以降の高速化の撤回とは別の判断になる。
3. booster-layoutは通常設定、cliparts-6x6は通常設定に `--remove-chroma-key-background` を加え、両方を4スレッドで測る。大画像の実測・工程時間・最終出力が得られるまで、小画像の結果だけで採用段階を決めない。
4. 比較には別の実行ファイル名と出力先を使う。タイムアウト・中断・完了を区別し、完了した場合にだけSVGと診断値を比較する。
5. 再適用する場合は上表の順番でパッチを確認する。まず、適用先が指定の比較元に一致することを確認する。

例えばコードが `725a082` 相当の場合、次のコマンドは最初のパッチが適用可能かだけを検査する。

```sh
git apply --check docs/performance-thread-2026-09/patches/01-initial-and-visibility.patch
```

実際の適用には `--check` を外すが、本書の作成では再適用していない。段階を飛ばした適用や最新コードへの重複適用を前提としない。古いコードに戻す前に、この新規文書ディレクトリも保存対象に含める。
